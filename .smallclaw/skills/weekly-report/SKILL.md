# 周报生成（Weekly Work Report）

把工作区资料与本周工作内容整理成一份**结构化 HTML 周报**：本周工作总结 + 关键数据/指标 + 问题与风险 + 下周计划。样式内联、独立可打开。

## 何时使用

- 用户明确要求"生成周报 / 写周报 / 做周报"
- 需要盘点工作区本周资料并输出结构化汇报

## 执行流程（严格按序）

### 第 1 步 · 盘点工作区
用 `list_files` 列出工作区文件，找出本周相关的资料、记录、数据文件；没有明确材料时先列文件再判断。

### 第 2 步 · 提取关键内容
用 `doc_inspect` 摸清结构，`doc_read` 提取正文（文档、表格、日志均可）；只提取与本周工作相关的部分。

### 第 3 步 · 整理证据表
梳理：本周完成事项、关键数据/指标、变化与问题。每条标注来源（文件/日期）。

### 第 4 步 · 输出结构化周报
固定结构，不得省略：
1. 本周工作总结
2. 关键数据（表格优先）
3. 问题与风险
4. 下周计划

### 第 5 步 · 生成 HTML
- `create_file` 一次性写入完整独立 HTML（内联样式，文档级 `<title>` 非空且反映主题）
- 文件名：`<本周>工作周报.html`（如 `2026-W41_工作周报.html`）
- 不需要免责声明，但必须含日期
- 生成后不要行级修补，需要修改就整文件重写

## 硬规则

1. **数据可追溯**：周报中的每项完成事项、数据必须来自工作区材料；材料没有的一律不写，需要推断的明确标注"推断"并给理由
2. **不编造**：缺失的关键数据用"（材料未提供）"占位，不猜测数值
3. **结构固定**：四段结构（总结/数据/问题/计划）不得省略或合并
4. **独立 HTML**：内联样式，无外部依赖，可直接浏览器打开
5. **多轮修正**：用户对周报提出修改时，直接改对应部分并整文件重写后重新交付

## 交付

- 周报写入工作区后，用文件交付能力把 HTML 呈现给用户
- 汇报时说明：读了哪些材料、关键数据来源、遗留缺口
