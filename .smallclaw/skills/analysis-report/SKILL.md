# 深度分析报告生成（Deep Analysis Report）

把任意材料（PDF、Word、Excel、扫描件、图片、文本、数据）分析成一份**结构化 HTML 分析报告**：信息头 + 时间线/关键数据表 + 分层分析 + 置信度结论 + 行动建议 + 总结 + 免责声明。样式体系固定（见 `templates/report.html`），内容按材料事实填充，**任何领域通用**（医学、技术、商业、职场、研究均可）。

## 何时使用

- 用户明确要求"分析 XX 并生成报告 / 深度分析 / 结构化报告 / HTML 报告 / 系统复盘"
- 材料包含大量数据、多时间点、多因素、因果链，纯文字回答难以结构化呈现
- 用户要求给出"结论 + 依据 + 建议 + 置信度"式的完整分析

## 执行流程（严格按序）

### 第 1 步 · 材料盘点与提取（只读工具，不臆测）
按材料类型选择提取工具，**逐个读完所有输入**：
- 文档/PDF/表格：先 `doc_inspect` 摸清结构，再 `doc_read` 提取内容（PDF 可指定页码）
- 扫描版 PDF（doc_read 返回 "no extractable text"）：用 `doc_ocr`（自动识别扫描页，或 pages='all' 强制）
- 医院检验单：`doc_parse_lab` 直接得到结构化数据（患者/日期/项目/异常/时间线）
- Excel 数据：`doc_read` 带 range 读取；`doc_inspect` 看 sheet 结构
- 图片/截图：用图片识别工具（image 工具族）
- 提取结果如需落盘，写到工作区，命名 `.xxx.extracted.txt`

### 第 2 步 · 关键事实提炼（数据必须可追溯）
从提取结果中整理**证据表**，每条标注来源（页码/日期/项目）：
- **时间线**：日期 + 该时间点的关键发现（变化、数值、结论）
- **关键指标**：数值、参考/对比值、异常方向（偏高/偏低）
- **矛盾点**：看似不一致但能统一解释的现象（如"指标 A 正常但症状 B 存在"）
- **分类数据**：可放入表格对比的条目

### 第 3 步 · 分层分析（通用推理框架）
按以下层次逐层分析，每层都要有材料证据支撑：
1. **格局判断**：先看整体机制（系统性/局部性、主因/次因），不被单项指标带偏
2. **关键数据解释**：逐个解释重要数值和矛盾点（趋势、比率、边界值、继发变化）
3. **排除法**：列出可排除的解释及其证据（证据链不完整时说明缺口）
4. **动态趋势**：时间序列变化说明什么（上升/下降/反复，与事件吻合度）
5. **核心画像**：用 2-3 句话概括最可能的解释，指出"看似合理但被低估的线索"

### 第 4 步 · 结论与置信度
- 分层结论：机制层面（高置信）→ 具体对象层面（中置信，列出其他可能）
- **置信度必须标注主观估计方法**（如"基于贝叶斯推理的主观估计"），并诚实说明：要达到更高置信必须补做什么
- "已可排除项"单独列出，逐条给证据

### 第 5 步 · 行动建议（按优先级）
- **表格**：优先级的验证/补证动作（做什么、为什么、成本）
- **立即可处理项**：列表形式（低风险、可马上做）
- 建议必须可执行、可验收，禁止空泛表述

### 第 6 步 · 总结
给决策者/家属/执行者的"三句话"：本质是什么、最关键的一句判断、下一步最有性价比的动作。

### 第 7 步 · 生成 HTML 报告
- 以 `templates/report.html` 为模板（**保持样式体系**：配色、表格、box、tag 结构），按上述内容填充
- 文档级 `<title>` 必须非空且反映主题（如"胸腔积液病因分析报告"）
- 产物写入工作区：`<主题>分析报告_<日期>.html`
- **免责声明必须保留**：数据来源、主观判断声明、不构成专业结论、重大决策请咨询专业人士

## 硬规则

1. **数据可追溯**：报告中的每个数字、日期、结论必须来自材料提取结果；材料没有的一律不写，需要推断的明确标注"推断"并给理由
2. **不编造**：缺失的关键数据用"（材料未提供）"占位，不猜测数值
3. **置信度诚实**：只对材料支撑充分的部分给高置信度；任何"95% 结论"都要有证据链
4. **样式稳定**：模板的 CSS 体系（#2c5f8a 主色、box/table/tag 样式）不得随意更改；内容替换即可
5. **报告形态**：必须是一个完整可独立打开的 HTML 文件（内联样式，无外部依赖）
6. **多轮修正**：用户对报告提出修改（替换/增删/调整结论）时，直接改对应部分并重新交付 HTML

## 交付

- 报告写入工作区后，用文件交付能力把 HTML 呈现给用户
- 汇报时说明：材料覆盖情况（读了哪些、OCR 了哪些页）、结论置信度、建议优先级、遗留缺口（哪些数据缺失/需补证）
